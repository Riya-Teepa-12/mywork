1) What the frontend does in Inkwell

The frontend is the part the user sees in the browser. In Inkwell it is built with React and it handles page rendering, form input, API calls, notifications, route protection, dashboard workflows, and UI updates.

The frontend talks to the backend through the API Gateway and updates the screen automatically when state changes.

Main idea: user action → React state change → API call → backend response → UI update.

2) Main frontend architecture

App-level routing

src/App.jsx decides which page opens for each URL, which routes are public, and which routes are protected.

Global auth state

src/context/AuthContext.jsx stores token, user, role, login/logout methods, and session persistence.

Notification context

src/context/NotificationContext.jsx shows toast messages and global UI notifications.

API layer

src/lib/api.js wraps fetch(), adds JWT, parses JSON, and centralizes error handling.

Service layer

src/lib/services.js organizes API calls by domain: auth, posts, comments, media, taxonomy, newsletter, notifications.

Feature pages

Pages like login, author dashboard, and admin panel implement the actual business workflows.

3) React concepts used in Inkwell frontend

useState useEffect useContext useNavigate useLocation useSearchParams useMemo useRef Conditional Rendering Controlled Components Protected Routes Page Animations
  • useState stores local values like form input, loading flags, error messages, and selected items.
  • useEffect runs side effects like API calls and localStorage sync.
  • useContext reads shared auth and notification data without prop drilling.
  • useNavigate moves the user to another page after login/logout or access checks.
  • useMemo optimizes derived calculations like counts and maps.
  • useRef stores DOM/editor references for scroll and editor actions.

5) `App.jsx` — main router

`App.jsx` is the root frontend component. It decides which page should open for which URL, protects private routes, and controls page transitions using Framer Motion.

Main ideas used here

  • useLocation() reads the current route path.
  • Routes and Route define the page mapping.
  • ProtectedRoute blocks unauthorized access.
  • PublicOnlyRoute blocks login/signup pages for logged-in users.
  • AnimatePresence and motion.div animate page transitions.

Important route groups

  • Public: home, feed, post details, author profile, suspended page
  • Public-only: login, signup, forgot password, OAuth callback
  • Protected: profile, notifications, newsletter, subscriptions
  • Author/Admin: author dashboard
  • Admin-only: admin panel
If a user is authenticated and suspended, `App.jsx` directly shows the suspended account page.

6) `AuthContext.jsx` — global auth manager

`AuthContext.jsx` is the heart of frontend authentication. It stores the JWT token, user, role, login state, and suspended state, and exposes actions like login, logout, signup, loginWithToken, and refreshProfile.

What it does

  • reads auth from localStorage
  • syncs auth changes back to localStorage
  • refreshes profile when token changes
  • auto-logs out if profile fetch fails
  • detects suspended accounts

Main hooks used

  • createContext creates shared auth context.
  • useContext lets components read auth data.
  • useState stores token and user.
  • useEffect syncs localStorage and refreshes profile.
  • startTransition updates auth state smoothly.

Auth actions

  • login() → calls `/auth/login` and stores token/user
  • signup() → calls `/auth/register`
  • loginWithToken() → used after OAuth/token-based login
  • logout() → calls backend logout and clears local auth
  • refreshProfile() → reloads profile from backend

Why this file matters

It avoids repeating auth logic in every page. Any component can simply call `useAuth()` to get login state and auth actions.

7) `LoginPage.jsx` — login screen

This page handles email-password login, Google OAuth, GitHub OAuth, and links to signup and forgot password pages.

React concepts used here

  • useState stores form input, loading state, and error state.
  • useEffect shows info messages and OAuth errors.
  • useNavigate redirects after successful login.
  • useLocation reads messages passed from other pages.
  • useSearchParams reads query params like OAuth errors.
  • useAuth() provides the login function.
  • useNotification() shows toasts.

Flow

  1. User types email and password.
  2. React stores values in state.
  3. User clicks Login.
  4. `handleSubmit()` calls `login(form)` from auth context.
  5. JWT and user profile come from backend.
  6. Frontend stores auth and navigates to home.

8) `AdminPanelPage.jsx` — admin dashboard

This is the most complex frontend page. It is a single dashboard that manages users, posts, categories, tags, comments, newsletters, broadcasts, subscriptions, media, audit logs, and author requests.

Main state areas

  • data lists: users, posts, comments, categories, tags, media, subscriptions, logs
  • filters: search text, role, active status, comment status
  • forms: category form, tag name, newsletter content, broadcast content
  • modal state: author requests and selected request details
  • UI state: loading, error, busy actions

How it loads data

The page uses `Promise.all()` to load many backend datasets in parallel. This makes the admin panel fast and organized.

Main helpers

  • load() → loads all dashboard data.
  • loadAuthorRequests() → loads author approval requests.
  • loadAuthorRequestDetails() → loads one request details.
  • decideAuthorRequest() → approve or reject an author request.
  • audit() → records admin actions.
  • runAction() → reusable try/catch wrapper for actions.

What the admin can do

  • change user roles
  • suspend or reactivate users
  • delete users
  • feature/unfeature posts
  • publish/unpublish posts
  • create/update/delete categories and tags
  • approve/reject/delete comments
  • send newsletters and post notifications
  • send broadcast notifications
  • delete media
  • review subscription records
  • see audit logs
  • review author requests

Why this file is important

It shows how one frontend page can orchestrate many services and many business actions in a single dashboard.

10) 2-minute frontend presentation script

The Inkwell frontend is built in React and acts as the user-facing layer of the application. The root file App.jsx controls routing, page transitions, and route protection. Authentication is managed globally in AuthContext.jsx, where token and user data are stored and synced with localStorage. API calls are centralized in api.js, and domain-wise API methods are grouped in services.js.

The login page uses controlled components, notifications, and OAuth redirects to authenticate the user. The author dashboard allows post creation, media upload, and comment moderation, while the admin panel provides full platform control over users, posts, categories, tags, comments, newsletters, subscriptions, media, audit logs, and author requests. Overall, the frontend is designed with reusable components, shared state, protected routes, and a clean service layer so the UI stays organized, scalable, and easy to maintain.
